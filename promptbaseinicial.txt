Atue como arquiteto sênior de software, analista de negócios, especialista em PHP/MySQL, segurança, LGPD, sistemas educacionais, checkout, certificação digital simples, financeiro educacional e backoffice administrativo.

Quero recriar do zero o projeto “Polo Rainbow”, um portal completo de cursos e eventos, mobile-first, com frontend público, área do aluno, backoffice administrativo, área do professor, checkout com PIX manual, cupons, certificados, área interna de cursos, financeiro com rateio para professores, logs, auditoria, lixeira, hardening, QA, deploy e documentação operacional.

A stack base deve ser:
- PHP MVC sem framework pesado
- MySQL 5.7
- Linux/cPanel
- `public_html` como pasta pública
- arquivos sensíveis fora de `public_html`
- frontend mobile-first
- rotas web e API preparadas
- controllers finos
- regras em services
- models simples
- logs e auditoria em tudo
- exclusões sempre com lixeira e justificativa
- compatibilidade com VS Code e Codex

## 1. Objetivo geral do sistema

Criar uma plataforma para venda, inscrição, entrega, acompanhamento e certificação de cursos e eventos, com controle administrativo completo.

O sistema deve permitir:
- listar cursos/eventos públicos em cards
- categorizar cursos/eventos
- exibir detalhes completos
- permitir inscrição individual, para terceiros e em lote
- aceitar cupom
- gerar pedido com pagamento via PIX manual
- receber comprovante PIX
- permitir análise administrativa do comprovante
- liberar acesso ao curso após aprovação
- exibir “Meus Cursos” para o aluno
- disponibilizar área interna do curso
- controlar progresso, presença e avaliação
- emitir certificado manualmente
- validar certificado publicamente por código/QR Code
- controlar financeiro e repasse para professores
- permitir gestão completa via backoffice
- permitir área restrita do professor
- registrar auditoria completa

## 5. Checkout e inscrição

### Regra geral
Não usar a palavra “comprar” no frontend principal; usar “Inscrever-se”.

Se usuário não estiver logado ao clicar em “Inscrever-se”:
- convidar para login ou cadastro
- após login/cadastro, retornar ao fluxo de inscrição

### Tipos de inscrição
O sistema deve permitir:
- inscrição para si
- inscrição para terceiros
- inscrição em lote

### Compra para terceiros
Separar:
- pagador
- comprador
- participante
- inscrição

O certificado sempre sai em nome do participante.

O comprovante PIX fica vinculado ao pagador/pedido.

O pagador pode acompanhar o status.

O participante pode criar conta própria depois, mas isso é opcional.

### Compra em lote
Uma empresa ou pessoa pode comprar várias vagas num único pedido.

Fluxo:
- um único PIX
- informar nome, CPF e e-mail ou CPF de cada participante
- cada participante gera uma inscrição própria
- pedido agrupa todos os participantes

### Pedido
Campos/conceitos:
- usuário pagador
- tipo de pedido
- valor bruto
- valor de desconto
- valor total
- status atual
- forma de pagamento
- observações internas
- data de expiração do pagamento
- aprovado por
- aprovado em
- cupom aplicado

Status do pedido:
- rascunho
- aguardando pagamento
- comprovante enviado
- em análise
- pendência
- aguardando reenvio
- pago
- aprovado
- cancelado
- expirado
- reembolsado

### Comprovante PIX
Regras:
- aceitar PDF, JPG, PNG
- tamanho máximo 3 MB
- apenas um comprovante atual por pedido
- permitir reenvio, mantendo histórico/versionamento
- professor nunca pode ver comprovantes PIX
- atendimento e financeiro podem analisar
- admin pode aprovar, reprovar ou solicitar reenvio
- solicitação de reenvio deve disparar e-mail
- tudo com histórico e auditoria

Campos:
- pedido
- arquivo
- nome original preservado
- caminho seguro interno
- versão
- is_atual
- status
- motivo de reenvio
- observação da análise
- analisado por
- analisado em

## 6. Cupons

Criar módulo completo de cupons.

### Regras
- curso em promoção não aceita cupom
- pode haver cupom de 100%
- cupom pode ser:
  - público
  - privado
  - vinculado a usuário específico
  - vinculado a empresa específica
- em compra em lote, cupom vale para o pedido inteiro
- se pedido for cancelado, uso do cupom não volta
- pode exigir quantidade mínima de vagas
- pode ter restrição por:
  - cidade
  - estado
  - perfil do usuário
  - tipo de curso
  - curso/evento específico
  - categoria
  - turma
- haverá links promocionais com cupom pré-preenchido
- apenas um cupom por pedido
- cupom percentual pode ter teto opcional de desconto
- cupom fixo não pode gerar total negativo
- cupom deve ser revalidado no fechamento do pedido

### CRUD de cupons
Campos:
- código
- nome interno
- descrição
- tipo: percentual ou valor fixo
- valor
- status
- validade inicial/final
- limite total de uso
- limite por usuário
- quantidade mínima de vagas
- valor mínimo do pedido
- aplicabilidade
- público/privado
- permite uso em lote
- permite pedido gratuito
- link promocional
- observações internas

Telas:
- listagem
- criação
- edição
- visualização
- resumo de uso
- histórico
- duplicar cupom
- encerrar cupom
- exclusão lógica com justificativa
